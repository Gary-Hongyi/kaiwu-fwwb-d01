# 腾讯开悟 · 服创 D01 参赛项目

这是我们参加腾讯开悟人工智能全球公开赛及第十七届中国大学生服务外包创新创业大赛 D01 赛道时留下的代码。项目分为两个阶段：初赛的峡谷追逐，以及复赛的王者荣耀 1v1 智能体。

**这个仓库是在比赛结束后重新整理建立的。** 比赛期间，我们主要通过文件夹副本、压缩包和平台上的代码进行迭代，没有持续使用 Git 管理版本。现在能找回的是部分源码快照、模型和说明材料，一些中间迭代、实验结果及修改过程已经缺失。因此，这里的 Git 历史从整理时开始，不能代表比赛期间完整的开发过程。

整理的目的，是把仍然保存下来的实现、版本关系和使用限制讲清楚，方便回顾，也方便后来阅读代码的人理解我们做过什么。

## 两个阶段的工作

| 阶段 | 保留的主要方案 | 代码位置 |
|---|---|---|
| 初赛：峡谷追逐 | PPO；数值特征与局部空间 CNN 融合，结合探索、追击躲避、宝箱、加速与闪现相关处理 | [projects/gorge_chase](projects/gorge_chase/) |
| 复赛：王者荣耀 1v1 | PPO；实体结构化特征、LSTM、多个价值头、自对弈、奖励塑形和动作规则 | [projects/hok1v1](projects/hok1v1/) |

初赛另保留了一套 DIY 规则方案，见 [archives/gorge_chase/diy_rules_20260410](archives/gorge_chase/diy_rules_20260410/)。这些方案是现存代码中能确认的实现，不代表每个方案都获得了充分、可复查的对照实验支持。

## 哪个是复赛最终提交版

`projects/hok1v1/` 来自原始 `代码.zip` 中的“复赛代码”，**项目作者已确认最后选择这一版本提交**。

原工作目录中另有一个名为“区域赛提交版”的文件夹。根据项目作者补充，这两份代码是在复赛某次迭代后分出的不同分支，并非简单的前后覆盖关系。那个文件夹的源码保存在 [archives/hok1v1/regional_branch](archives/hok1v1/regional_branch/)，没有与最终提交版合并。

共同分支点的原始快照和完整迭代记录没有保留下来，因此目前只能确认两份现存源码的差异，不能还原精确的分支时间、提交序列或每次实验的效果。具体见 [版本与来源说明](docs/version-history.md)。

## 如何使用

比赛期间，这些代码是在腾讯为参赛队伍提供的官方平台 Dev 环境中运行和迭代的。这个仓库保留的是该平台上的参赛工程，完整训练和对局依赖平台提供的游戏环境及运行组件。普通电脑上仅安装 PyTorch 和 NumPy，并不等同于原来的参赛运行环境。

在对应的开悟 Dev 环境中，将选定项目目录作为代码根目录，检查环境配置和平台模型编号，再使用其中的 `train_test.py`。这个脚本是短训练测试入口，其小样本参数与正式训练配置不同。本次赛后整理未重新接入原比赛平台做完整对局复现。详情见 [运行说明](docs/runtime.md) 和两个项目目录下的 README。

仓库可以在本地做不依赖游戏环境的文件完整性与语法检查：

```bash
python scripts/verify_repository.py
```

## 当前保留范围与限制

- 核心源码和配置保持来源文件的内容，通过哈希清单记录；整理时移出了 V2 残留检查脚本，没有重写参赛算法。
- 一些旧特征模块、备选 DIY 实现仍然保留。文件存在不等于当前训练路径会调用它们。
- V2 试验只找到了检查脚本，对应实现缺失，已独立归档，不能作为可运行方案。
- 初赛曾保存的权重，以及复赛另一分支附带的第 292449 步权重，仍保存在原始本地资料中，本次不随仓库提交。不能确认该复赛权重与最终提交源码严格对应。
- 没有足够完整的实验记录支撑重新报告胜率、消融结论或各版本收益，因此 README 不补写这些数字。
- 区域赛技术稿、决赛答辩讲稿和六份 PPT 变体已分类保留，见[比赛资料索引](docs/competition/document-index.md)和[命名依据](docs/organization-and-naming.md)。讲稿中的未来设想不应读作已经实现的功能。会议纪要、证书、客户端和回放文件不随仓库提交。

整理检查的范围与结果见 [validation.md](docs/validation.md)。本地代码检查和模型前向检查不等于平台训练、真实对局或比赛成绩复现。
