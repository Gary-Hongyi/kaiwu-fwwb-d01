# 代码结构与主要实现

本文说明现存代码中可见的实现，不补写性能数字或算法贡献归属。

## 通用布局

每个运行根目录内保留开悟工程习惯：`agent.py` 作为智能体入口，`model/` 定义网络，`algorithm/` 负责学习更新，`feature/` 处理观测、奖励和样本，`workflow/` 编排对局，`conf/` 定义维度、参数和环境。

`conf/app_conf_*.toml` 选择策略，`conf/algo_conf_*.toml` 把算法名称映射至 Agent 与工作流。`train_test.py` 调用平台短训练测试工具；不能把其中的微型样本池设置当作正式训练参数。

## 初赛：峡谷追逐

主 PPO 方案将数值状态与四通道 21×21 局部空间信息分别编码，数值分支使用 MLP，空间分支使用 CNN，再融合为策略和价值输出。动作输出为 16 维，价值输出为单头。

`preprocessor.py` 除特征构建外还包含奖励处理，涉及宝箱、加速、探索/重复访问、死路、运动、逃生与闪现。该文件保留了跨步记忆，例如访问次数、近期位置、阻塞方向与加速点状态。

独立 DIY 快照以 `rule_policy.py` 对合法动作评分。主 PPO 目录里的 DIY 部分则是另一套扩展模板，不与规则快照混为一谈。

## 复赛：王者荣耀 1v1

1. `unpack_state_dict.py` 将当前协议的原始观测组织为英雄、技能、机关、小兵、河蟹和飞行物等对象。
2. `obs_builder.py` 构建 4348 维结构化特征。
3. `model/model.py` 分实体编码与融合，通过 512 维 LSTM 处理时序，输出六组动作 logits 和五组价值。
4. `agent.py` 完成采样、合法性修复、目标选择、安全推塔、状态重置与模型生命周期。
5. `reward_manager.py` 逐帧计算奖励，`definition.py` 整理多头回报与优势和 LSTM 序列，`algorithm.py` 更新参数。
6. `train_workflow.py` 管理对局、自对弈对手与监控数据。

五组价值头为经济发育（farm）、击杀死亡（kda）、伤害（damage）、推进（push）和状态（state）。最终提交版比同源归档分支额外配置了拉扯攻击、残血回撤和兵线掩护奖励。

旧 `feature/feature_process/`、旧 `reward_process.py` 与备选 `agent_diy/` 仍保留，便于理解代码迁移背景；当前 PPO 主路径未使用旧特征入口。V2 检查脚本已另行归档，缺少对应实现。
