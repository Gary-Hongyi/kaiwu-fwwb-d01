五、特征与规则 （郭）

本节主要介绍本队在原始观测特征处理和规则后处理方面的改动。与官方 baseline 相比，我们没有继续沿用低维手工特征，而是重新构建了面向 1v1 MOBA 场景的结构化特征体系，并在推理阶段加入合法动作修复、安全推塔、召唤师技能选择和状态重置等规则，使模型输出更稳定、更贴近比赛胜利目标。

baseline1 的特征处理主要由 `feature_process` 模块完成，输入维度为 10 维，包含己方英雄是否存活、英雄坐标、敌方防御塔坐标、相对位置和塔血比例等少量信息。该设计可以跑通 PPO 训练流程，但对本赛题而言表达能力不足：模型难以感知技能冷却、兵线状态、塔攻击目标、敌方飞行物、经济变化、buff 状态和目标合法性等关键信息。因此，我们将特征处理重构为 `unpack_state_dict.py + obs_builder.py` 两级流程：前者负责解析原始环境字典，后者负责构造固定长度特征向量。

| 模块 | baseline1 | 当前版本 |
|---|---|---|
| 特征维度 | 10 维 | 4348 维 |
| 主要实体 | 己方英雄、敌方防御塔 | 双方英雄、双方小兵、双方防御塔、河蟹、血包、敌方飞行物 |
| 位置表达 | 原始/相对坐标 | 相对位置 one-hot、归一化距离、全图坐标分桶、桶内偏移 |
| 技能信息 | 基本未覆盖 | 召唤师技能、主动技能冷却、技能可用性 |
| 动作处理 | 主要依赖采样时的 legal action mask | 采样 mask + 推理后动作修复 + 目标头重选 + 安全推塔规则 |

1. 原始状态解析与实体重组

官方环境返回的 `frame_state` 同时包含英雄、NPC、子弹和功能物件等多类信息，字段层级较深，且不同实体的含义需要结合 camp、sub_type、runtime_id 等字段判断。为了避免在奖励、特征和规则中重复解析这些字段，我们在 `agent_ppo/feature/unpack_state_dict.py` 中建立了统一的状态适配层。

该适配层会根据 camp 和 player_id 区分己方与敌方英雄；根据 NPC 的 sub_type 区分防御塔、水晶、泉水、小兵和河蟹；根据子弹的 source_actor 将飞行物划分为英雄子弹、机关子弹和小兵子弹；同时维护 runtime_id 到实体类型的映射，用于判断防御塔当前攻击的是英雄还是小兵。经过这一步处理后，后续模块可以直接访问 `hero_our`、`hero_enemy`、`soldiers_our`、`organ_enemy.sub_tower`、`bullets_enemy.hero` 等对象，减少了原始协议字段变化带来的风险。

2. 实体级特征扩展

当前版本的特征由多个实体组拼接而成，总维度为 4348，其中实体特征 2758 维，飞行物特征 1590 维。具体包括：

己方和敌方英雄各 372 维。英雄特征包含英雄 ID、行为状态、能量比例与能量分桶、召唤师技能类型、五个技能槽的冷却与可用状态、等级、经济变化、草丛状态、防御塔关系、buff 信息、血量与位置等。英雄 ID 用连续编码区分鲁班七号和狄仁杰，行为状态用 one-hot 表示死亡、移动、普攻、技能释放等状态；技能冷却同时保留比例值和分桶编码，使模型既能判断当前技能是否可用，也能估计技能恢复时间。

双方小兵各保留 4 个，每个小兵 184 维。小兵特征包括行为状态、兵种类型、是否进入对方塔攻击范围、是否正在被塔攻击、血量和位置。小兵按 runtime_id 排序并截断到固定数量，不足部分补零。该部分信息对射手英雄尤其重要，因为推塔和换血都依赖兵线保护；模型需要知道小兵是否已经进入塔下、是否正在吸引塔仇恨，才能学到“有兵线推进、无兵线避战”的策略。

双方防御塔各 181 维。塔特征除血量和位置外，还加入攻击目标类型、血包是否存在、血包刷新时间估计等信息。相比 baseline 只保留塔血和塔位置，当前特征能让模型判断塔当前是否正在攻击小兵，从而识别更安全的点塔窗口。

此外，我们还加入河蟹 180 维和敌方飞行物 1590 维。飞行物按距离选择最近的敌方英雄飞行物和机关飞行物，编码其技能槽类型和位置，用于补充技能威胁和塔弹威胁信息。虽然飞行物不是每一帧都存在，但在对拼、撤退和塔下推进时，它能帮助模型更及时地感知危险来源。

3. 归一化与分桶编码

原始坐标、血量、经济和技能冷却的数值范围差异较大，直接输入会增加训练难度。因此我们采用“比例值 + 分桶 one-hot”的方式处理连续特征。

位置特征分为相对位置和全局位置两部分。相对位置以己方英雄为中心，记录目标相对坐标分桶和归一化距离，帮助模型判断敌人、小兵、塔和飞行物是否处于攻击、追击或撤退范围内；全局位置记录地图坐标分桶和桶内偏移比例，用于保留推进方向、塔前区域、基地附近等宏观位置信息。

血量特征同时保留血量比例和血量分桶，避免仅使用绝对血量导致不同等级之间难以比较，也避免仅使用比例值丢失关键血量区间。经济特征记录双方累计经济比例和 money_total 的帧间变化，帮助模型捕捉补兵、击杀和资源获取带来的增量收益。

4. 目标选择特征

本赛题动作空间包含目标头，目标选择质量直接影响普攻、技能和召唤师技能的实际效果。当前版本为目标选择保留固定候选顺序，包括空目标、敌方英雄、己方英雄、敌方小兵、敌方防御塔和河蟹等。不存在或不可见的实体使用补零处理，避免模型把无效目标当作真实目标学习。

这一设计与网络中的 target attention 分支相配合。模型会根据候选目标的血量、距离、是否存在、是否在塔范围内等信息生成目标 logits；推理阶段则进一步结合当前 button 对应的合法目标 mask，保证目标头与主动作保持一致。例如，普攻和技能类动作会优先选择真实目标，减少可攻击时仍选择空目标的问题。

5. 合法动作修复

baseline1 在动作采样阶段使用 legal_action 做 masked softmax，但 `action_process` 基本直接返回采样动作或最大概率动作。当前版本在 `agent_ppo/agent.py` 中加入了更完整的推理后处理：模型输出后，先对动作维度进行裁剪，再按动作空间 `[12, 16, 16, 16, 16, 9]` 拆分 `legal_action`，分别校验 button、方向参数、技能参数和目标头是否合法。

若主按钮非法，则按照预设 fallback 顺序选择合法动作；若某些方向或技能参数在当前 button 下不需要使用，则回退到默认值；若目标头非法，则根据最终 button 重新选择合法目标。当 `legal_action` 缺失、长度异常，或英雄处于死亡/复活状态时，系统会使用默认动作和默认概率分布兜底，避免异常观测导致推理崩溃。

这部分规则的目标不是替代模型决策，而是保证模型输出能够被环境执行。对于层次化动作空间而言，button、方向和 target 之间存在依赖关系，如果只依赖网络原始输出，容易出现“主动作合法但目标非法”“技能不需要方向却输出方向”“有目标却选空目标”等问题。动作修复降低了这些无效动作带来的样本噪声。

6. 安全推塔后处理

由于比赛胜利条件是摧毁对方防御塔，我们在推理阶段加入了一条较保守的安全推塔规则。该规则只在同时满足以下条件时触发：己方英雄存活且血量比例不低，敌方防御塔存活，己方小兵已经在塔附近或英雄附近形成保护，英雄距离敌方塔处于可攻击范围附近，敌方英雄不构成近距离威胁，并且“普通攻击敌方防御塔”在当前 `legal_action` 和 `sub_action_mask` 中均合法。

在满足上述条件时，如果模型当前动作不是指向敌方英雄的击杀或对拼动作，则将动作修正为普通攻击敌方防御塔。这条规则主要解决训练后期观察到的“已经有兵线和安全窗口，但模型在塔边徘徊或继续选择低收益目标”的问题。我们同时保留敌方英雄击杀窗口的优先级，如果模型已经选择攻击敌方英雄，则不会强行改为打塔，避免错过残血击杀机会。

7. 召唤师技能与状态规则

在召唤师技能选择上，baseline1 采用随机选择可用召唤师技能的方式。考虑到本赛题主要英雄为鲁班七号和狄仁杰，二者都依赖普攻和短时爆发，我们最终统一选择狂暴。特征侧显式编码召唤师技能类型和冷却状态，奖励侧通过 `frenzy_use` 评价释放质量，从而引导模型把狂暴用于有效对拼、追击或击杀窗口，而不是开局空放或低血量逃跑时误放。

此外，我们维护了英雄死亡、复活和 deadCnt 变化状态。当检测到新死亡、复活或处于死亡/复活行为状态时，会重置 LSTM hidden/cell 状态。这样可以避免上一条生命中的战斗历史继续影响复活后的决策，因为死亡后英雄位置、兵线、塔血和敌我距离往往已经发生明显变化。

总体来看，本队在第五部分的核心改动可以概括为“结构化特征扩展 + 稳定归一化 + 合法动作修复 + 保守规则兜底”。相比 baseline 的低维手工特征，当前输入更完整地描述了英雄、小兵、防御塔、飞行物和地图资源之间的关系；相比纯端到端动作输出，后处理规则又保证最终动作尽量合法、稳定且服务于推塔胜利目标。这些改动在训练和评估阶段保持一致，减少了非法动作和异常状态带来的噪声，也为模型学习对线、拉扯、补兵和推进提供了更清晰的状态基础。
