# 来源、整理操作与保留范围

## 来源追踪

`source_manifest.json` 记录每个保留来源文件的仓库路径、原 ZIP/目录内路径、字节数及 SHA-256，同时记录三份使用到的源 ZIP 的哈希。三份更正演讲人姓名的 PPT 还记录原文件的哈希、字节数和更正说明。这个清单便于核对整理副本与原资料，不代表能认证平台上传或实验效果。

来源路径为原资料中的相对路径，不包含本机用户目录。原压缩包、模型、文档与客户端继续保留在原工作目录。

## 本次整理做了什么

- 选择 `代码.zip` 中的初赛 PPO 和作者确认的复赛最终源码，分别展开至 projects。
- 将 DIY 规则方案、复赛同源分支和两份基线分开保存。
- 将最终复赛源码中的四个 V2 检查脚本移至独立归档；区域赛分支里的相同脚本不重复保留。
- 排除 Python 缓存、权重、IDE 私有设置、二进制客户端与原始归档。
- 新增 README、运行/架构/历史说明、忽略规则和完整性检查工具。
- 补入三份复赛特征与规则技术稿、三份可正常读取的复赛讲稿和六份区域赛决赛答辩 PPT；材料按用途重命名。除三份 PPT 按项目作者确认更正演讲人姓名外，保留来源文件与原文件逐字节一致；更正前后哈希及来源路径记录于清单。
- 保留其他源码及运行配置的字节内容，没有重新调奖励、改网络、替换模型池编号或拼接分支。
- 通过 `.gitattributes` 禁用自动换行转换，避免跨平台检出时破坏来源文件的字节哈希。
